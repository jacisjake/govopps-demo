Harness C — one facet object, two consumers

C is not two systems that happen to share a vibe. It is one frozen facet ticket. The runtime writes it from conversation and artifacts. Deterministic search reads it. The eval runner asserts it. The model never searches, never tiers, never invents a URL.

What C looks like

Founder language is messy: a URL, a deck, a pasted pitch, a chat turn. Federal search is not. Grants.gov, SAM, SBIR, USAspending, and regional sources want codes, agencies, mechanisms, dates, geography, set-asides.

The harness is the translator and the lie detector. Same schema. Runtime emits a ticket. Tests open the same ticket and mark pass / fail against the five brief cases (and later, live pulls).

Runtime half

Turns this session’s evidence into one ticket. Interview may revise the ticket. Search only sees the ticket, never the raw pitch.

Eval half

Feeds the five mock companies through the same runtime (or a recorded ticket) and checks the ticket — not McKenna’s prose — against expected facets.

The facet ticket

This is the contract. If a field is not on the ticket, search may not use it. If a field is on the ticket, eval can assert it. Provenance stays on every field: stated · inferred · unknown.

profile is who they are. query is the translation (the brief’s central job). search_plan is that translation compiled into per-source parameters — the deterministic features. qwen may propose a plan; a compiler (rules, not the model) has to accept it before any HTTP call.

Runtime — write the ticket, then search

One question at a time. Each turn updates the ticket, then the compiler asks: would another question change retrieve? If no, freeze and search.

sequenceDiagram participant F as Founder participant M as McKenna / qwen participant C as Compiler participant T as Facet ticket participant A as Source APIs F->>M: pitch, URL, or answer M->>T: patch fields + provenance T->>C: validate / compile search_plan alt plan would collapse the set C->>M: surface tradeoff, do not silently drop M->>F: one discriminating question else ticket is sufficient C->>T: freeze C->>A: Grants.gov · SAM · SBIR · USAspending · regional A-->>C: normalized rows C->>F: Opportunity Map (score, not chat) end

After freeze, scoring is the existing v0.3 gates + weights. History (USAspending / SBIR awards) is attached to every served card as evidence, not as a vibe.

Eval — same ticket, known companies

The five brief startups are fixtures, not prompts we hope go well. Each fixture is: raw input (the mock site / pitch) + an expected ticket (facets that must appear) + expected map shape (sources hit, agencies, honest no-match for Rallytime).

Failures are structured: missing required facet, forbidden inference (ownership guessed), source not queried, history block empty, URL not in retrieve set. A pretty card with a wrong ticket is a fail.
